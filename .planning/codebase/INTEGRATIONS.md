# External Integrations

**Analysis Date:** 2026-04-17

## APIs & External Services

**Market Data:**
- Sibling `asset_prices` project - `main.py` and `predict_prophet.py` inject `ASSET_PRICES_REPO` into `sys.path` and import `lib.read_utils.read_symbol_data` to read market data
  - SDK/Client: external Python module `lib.read_utils` from the repo pointed to by `ASSET_PRICES_REPO`
  - Auth: `ASSET_PRICES_REPO`, `ASSET_PRICES_DATA_DIR`, `ASSET_PRICES_DATA_TYPE`
- Alpaca market data - selected through `--source alpaca` in `main.py` and `predict_prophet.py`, but accessed indirectly through the external `asset_prices` reader rather than direct SDK calls in this repo
  - SDK/Client: `alpaca-trade-api==3.2.0` in `requirements.txt`
  - Auth: not handled in this repository; any provider credentials are upstream of `main.py`
- Yahoo Finance - selected through `--source yfinance` in `main.py` and `predict_prophet.py`, also accessed indirectly through the external `asset_prices` reader
  - SDK/Client: `yfinance==0.2.49` in `requirements.txt`
  - Auth: none detected in this repository

**Email Delivery:**
- Gmail SMTP - alert delivery is handled by `send_gmail.py`, and `main.py` calls it when regression bands change
  - SDK/Client: Python stdlib `smtplib` plus `email.mime.*` in `send_gmail.py`
  - Auth: `GMAIL_ADDRESS` and `GMAIL_APP_PASSWORD` loaded from `~/.gmail_send/.env`

**Frontend Assets in Generated Output:**
- Plotly CDN - `main.py` exports HTML with `include_plotlyjs='cdn'`, so generated chart pages fetch Plotly JavaScript at render time in the browser
  - SDK/Client: `plotly==5.24.1`
  - Auth: none

## Data Storage

**Databases:**
- Not detected

**File Storage:**
- Local filesystem only for this repository's own outputs: `main.py` and `predict_prophet.py` write charts into `./plots/`
- External parquet dataset on local/shared storage via `ASSET_PRICES_DATA_DIR`, consumed by `read_symbol_data(...)` from `main.py` and `predict_prophet.py`
- Recipient configuration is stored locally in `email_recipients.txt`

**Caching:**
- None

## Authentication & Identity

**Auth Provider:**
- Gmail App Password authentication in `send_gmail.py`
  - Implementation: `send_gmail.py` opens `~/.gmail_send/.env`, parses `GMAIL_ADDRESS` and `GMAIL_APP_PASSWORD`, then authenticates to `smtp.gmail.com:587` with STARTTLS
- No user login, session auth, OAuth flow, or application-level identity layer is implemented in `main.py`

## Environment Configuration

**Required env vars:**
- `ASSET_PRICES_REPO` - imported by `main.py` and `predict_prophet.py` to locate the sibling `asset_prices` codebase
- `ASSET_PRICES_DATA_DIR` - imported by `main.py` and `predict_prophet.py` to locate parquet data
- `ASSET_PRICES_DATA_TYPE` - imported by `main.py` and `predict_prophet.py` to choose adjusted vs. raw data
- `GMAIL_ADDRESS` - read by `send_gmail.py`
- `GMAIL_APP_PASSWORD` - read by `send_gmail.py`

**Secrets location:**
- Gmail SMTP secrets live in `~/.gmail_send/.env` outside the repository and are referenced by `send_gmail.py`
- No in-repo secret files were detected
- Market-data provider secrets are not read directly by this codebase; they are presumed to be handled by the external `asset_prices` workflow selected by `main.py`
